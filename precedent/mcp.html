Using Precedent from external AI assistants (MCP)

Precedent declares a rovo:mcp module named Precedent decisions that exposes six tools:

Tool Verb What it does
search-decisions GET Search what was decided and why
get-decision GET Fetch one decision (e.g. DEC-12)
check-conflicts GET Check an issue key or free-text proposal against past decisions
decisions-for-work-item GET List the decisions that apply to a Jira issue
record-decision CREATE Record a decision (confirm with the user first)
supersede-decision UPDATE Mark an older decision as superseded

Every call runs with the invoking user's permissions. Results are filtered to decisions whose sources that user can open.

In Rovo Studio

Go to Create agent → Tools → Add tools → Connected apps → Precedent, then pick the tools you want. The bundled Decision Keeper agent already uses all of them through the precedent-decisions skill.

In Claude Code, Claude Desktop, Cursor or VS Code (Early Access)

  1. An org or site admin enables the tools under admin.atlassian.com → Apps → Sites → (site) → Connected apps → Precedent → Tools.
  2. Add the server. <appId> is the UUID at the end of app.id in manifest.yml:
    claude mcp add --transport http precedent https://mcp.atlassian.com/forge/<appId>
    Other clients: add an HTTP MCP server with the same URL.
  3. Authenticate with OAuth in the browser, pick the site, and approve the scopes.
  4. Optional: give your agent the open-source skill at skills/precedent-decisions/SKILL.md. It explains when to call each tool and how to report conflicts.

Third-party client access to Forge MCP servers is an Atlassian Early Access feature. It is experimental and may change.

Example prompts:

  • "Before I open this PR that adds a GraphQL gateway, check our past decisions."
  • "Record the decisions from today's architecture sync" (then paste the notes).
  • "Which decisions are due for a revisit?"
